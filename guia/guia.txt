GUIA DE EJECUCION - MEDIQUEUE MICROSERVICIOS
Fecha: 2026-05-20

Esta guia usa PowerShell desde la raiz del proyecto:
B:\Proyecto BD II Microservivios

Objetivo:
- Reconstruir contenedores.
- Levantar el backend normal.
- Levantar el backend con 2 replicas por microservicio.
- Preparar datos para pruebas.
- Ejecutar pruebas k6 de 1k, 5k, 10k, 12k, 15k, 20k, 25k y 50k rpm.

IMPORTANTE:
- Para pruebas limpias, usa DATA_OFFSET distintos en cada prueba.
- Si repites el mismo DATA_OFFSET sobre datos ya usados, puedes obtener conflictos o validaciones.
- Si quieres forzar conflictos, ejecuta una prueba dos veces con el mismo DATA_OFFSET y mismo dataset.
- Para pruebas de maximo rendimiento de creacion usa el perfil creation-only.
- Para probar flujo completo appointment -> RabbitMQ -> payment -> notification usa el perfil E2E completo.


============================================================
1. COMANDOS BASICOS DE DOCKER COMPOSE
============================================================

Ver estado:

docker compose ps

Ver logs generales:

docker compose logs --tail=100

Ver logs de servicios principales:

docker compose logs --tail=100 api-gateway appointment-service patient-service schedule-service payment-service notification-service

Detener contenedores sin borrar volumenes:

docker compose down

Detener y borrar volumenes de datos:

docker compose down -v

ADVERTENCIA:
docker compose down -v borra datos de PostgreSQL, Redis, RabbitMQ, etc.
Usarlo solo cuando quieras reiniciar la base desde cero.


============================================================
2. REHACER / RECONSTRUIR CONTENEDORES
============================================================

Reconstruir todos los servicios:

docker compose build

Reconstruir servicios principales:

docker compose build api-gateway appointment-service patient-service schedule-service payment-service notification-service

Reconstruir sin cache:

docker compose build --no-cache api-gateway appointment-service patient-service schedule-service payment-service notification-service

Reconstruir y levantar:

docker compose up -d --build

Validar configuracion Compose:

docker compose config --quiet


============================================================
3. LEVANTAR BACKEND NORMAL
============================================================

Levantar todo normal:

docker compose up -d

Levantar solo ruta principal del backend:

docker compose up -d api-gateway appointment-service patient-service schedule-service payment-service notification-service

Revisar salud:

docker compose ps api-gateway appointment-service patient-service schedule-service payment-service notification-service

Probar gateway:

Invoke-WebRequest -UseBasicParsing http://localhost:8080/actuator/health


============================================================
4. LEVANTAR CON 2 REPLICAS POR MICROSERVICIO
============================================================

Usar este comando para pruebas de carga balanceadas:

docker compose up -d `
  --scale api-gateway=2 `
  --scale appointment-service=2 `
  --scale patient-service=2 `
  --scale schedule-service=2 `
  --scale payment-service=2 `
  --scale notification-service=2 `
  api-gateway appointment-service patient-service schedule-service payment-service notification-service

Verificar replicas:

docker compose ps api-gateway appointment-service patient-service schedule-service payment-service notification-service

Volver a 1 replica:

docker compose up -d `
  --scale api-gateway=1 `
  --scale appointment-service=1 `
  --scale patient-service=1 `
  --scale schedule-service=1 `
  --scale payment-service=1 `
  --scale notification-service=1 `
  api-gateway appointment-service patient-service schedule-service payment-service notification-service

============================================================
17. COMO INTERPRETAR RESULTADOS
============================================================

Prueba limpia ideal:

appointments_503=0
appointments_server_error=0
appointments_timeout=0
appointments_connection_refused=0
dropped_iterations=0
checks_rate=1

Si aparece:

dropped_iterations > 0

Significa que k6 no pudo sostener el ritmo configurado. Puede ser por:
- backend saturado,
- latencia alta,
- falta de VUs,
- limite de CPU/RAM de Docker,
- dataset con validaciones que consumen tiempo.

Si aparece:

appointments_503 > 0

Significa que el gateway o el balanceador devolvio indisponibilidad.
Revisar:

docker compose logs --tail=200 api-gateway appointment-service

Si aparece:

appointments_validation_error > 0

Significa que las solicitudes fueron rechazadas por reglas de validacion.
Puede pasar por:
- slots no validos,
- pacientes no validos,
- dentists/slots ya usados,
- DATA_OFFSET cruzado,
- dataset agotado o contaminado por pruebas anteriores.

Si aparece:

Insufficient VUs

No significa solamente "faltan VUs".
Normalmente significa que las respuestas tardan mucho y k6 necesita muchos usuarios virtuales para mantener el ritmo.


============================================================
18. PRUEBA PARA FORZAR CONFLICTOS
============================================================

Para forzar conflictos de slots:
1. Ejecuta una prueba limpia.
2. Repite la misma prueba con el mismo DATA_OFFSET.

Ejemplo:

$env:BASE_URL="http://localhost:8080"
$env:DATA_FILE="../data/appointments-50000.json"
$env:RATE_PER_MINUTE="1000"
$env:DURATION="1m"
$env:TOTAL_LIMIT="1000"
$env:DATA_OFFSET="0"
$env:PRE_ALLOCATED_VUS="120"
$env:MAX_VUS="300"
$env:CLIENT_MODE="per-vu"
$env:HTTP_TIMEOUT="60s"
$env:DEBUG_RESPONSES="false"

k6 run .\infra\load-tests\appointments\scripts\appointment-rpm.js `
  --summary-export .\infra\load-tests\appointments\results\appointment-rpm-conflict-pass1-summary.json

k6 run .\infra\load-tests\appointments\scripts\appointment-rpm.js `
  --summary-export .\infra\load-tests\appointments\results\appointment-rpm-conflict-pass2-summary.json

En la segunda ejecucion deberian aparecer conflicts o validation errors, dependiendo de como responda la API ante slots ya ocupados.

19. COMANDOS UTILES DESPUES DE CADA PRUEBA
============================================================

Ver estado de contenedores:

docker compose ps api-gateway appointment-service patient-service schedule-service payment-service notification-service

docker compose logs --tail=200 api-gateway appointment-service

Ver metricas basicas de recursos:

docker stats

Ver historial Flyway:

docker exec mediqueue-postgres psql -U mediqueue -d mediqueue -c "select 'appointment' as schema, version, description, success from appointment.flyway_schema_history union all select 'patient', version, description, success from patient.flyway_schema_history union all select 'schedule', version, description, success from schedule.flyway_schema_history union all select 'payment', version, description, success from payment.flyway_schema_history union all select 'notification', version, description, success from notification.flyway_schema_history order by schema, version;"
